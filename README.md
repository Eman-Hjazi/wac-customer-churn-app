# Customer Churn Prediction & Retention Advisor

A Streamlit application for exploring telecom customer churn, predicting churn risk, and presenting retention recommendations. The project combines a scikit-learn model-training workflow with a web dashboard and an optional Gemini-powered retention advisor.

> **Project context:** WAC Day 5 – Example 1 (Model Benchmarking & Artifact Serialization) and Example 2 (Trainer Live Web Application).

## Overview

The project is organized into two Python programs:

- **`day5_ex1_train_and_save.py`** prepares the training data, benchmarks two classifiers, selects the winner, calculates feature-importance information, and saves the model artifacts.
- **`day5_ex2_trainer_app.py`** loads the saved artifacts and runs the Streamlit dashboard. It does not retrain the model when the dashboard starts.

The current training configuration runs the **Trainer – Telecom Customer Churn** dataset. The Group A, Group B, and Group C example calls are optional examples and may remain commented out until their datasets are available.

## Features

- **Customer KPIs:** total customers, historical churn rate, average monthly bill, and number of high-complaint accounts.
- **Interactive filters:** filter customers by city and contract type.
- **Churn-risk prediction:** enter customer details and receive a model prediction and predicted churn probability.
- **Feature-importance chart:** display the top model features used by the trained classifier.
- **Retention recommendations:** generate three short retention actions with Gemini 2.5 Flash when configured, or use the local rule-based fallback when Gemini is unavailable.
- **Cached resources:** use Streamlit caching for data and model artifacts.

    ├── churn_model.pkl

The `models/` directory is generated by the training script. The three saved artifacts are:

| Artifact | Purpose |
|---|---|
| `churn_model.pkl` | The winning trained classifier. |
| `churn_columns.pkl` | The feature names and exact column order expected by the model. |
| `churn_importance.pkl` | Feature-importance values or absolute Logistic Regression coefficients for display. |

## Dataset

The Trainer dataset is expected to be named **`customer_churn.csv`** and placed in the repository root.

The current training and application code expects these columns:

| Column | Description | Use |
|---|---|---|
| `customer_id` | Customer identifier | Removed before model training. |
| `city` | Customer city | Feature; categorical. |
| `contract_type` | Contract type | Feature; categorical. |
| `tenure_months` | Customer tenure in months | Feature. |
| `monthly_bill_usd` | Monthly bill amount in USD | Feature. |
| `support_calls` | Number of support calls | Feature. |
| `churn` | Churn outcome | Target. |

The model code assumes a binary target encoded as **`0` = no churn** and **`1` = churn**. The dashboard uses class `1` as the churn class when displaying the prediction and probability. Confirm that the dataset uses this encoding before training or publishing results.

The training script applies one-hot encoding to `city` and `contract_type`. It also uses `drop_first=True`; the dashboard aligns prediction input columns with the saved training columns before calling the model.

## Setup and run locally

### 1. Clone or download the repository

```bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd wac-customer-churn-app
```

### 2. Create and activate a virtual environment (Windows PowerShell)

```powershell
py -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. Install dependencies

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Make sure `requirements.txt` contains the libraries used by this project, including `streamlit`, `pandas`, `numpy`, `scikit-learn`, and `joblib`. Add `google-genai` when using the Gemini integration.

**Model compatibility:** use the same Scikit-learn version for training and loading the saved `.pkl` model artifacts. Record and pin the version used to generate the artifacts in `requirements.txt`.

### 4. Check the project paths

Both Python files should load the CSV and model artifacts from the project directory rather than from a machine-specific absolute path. A common pattern is:

```python
from pathlib import Path

BASE_DIR = Path(__file__).resolve().parent
DATA_PATH = BASE_DIR / "customer_churn.csv"
MODELS_DIR = BASE_DIR / "models"
```

In `day5_ex1_train_and_save.py`, set the Trainer dataset path to `DATA_PATH` (or `str(DATA_PATH)`). In `day5_ex2_trainer_app.py`, use `DATA_PATH` and `MODELS_DIR` when reading the CSV and loading the `.pkl` files.

### 5. Train the model and create the artifacts

Run this command from the repository root:

```powershell
python day5_ex1_train_and_save.py
```

The script compares `LogisticRegression` and `RandomForestClassifier` using the test split, reports Accuracy and Recall, selects the model with the higher Accuracy, and writes the artifacts to `models/`.

### 6. Start the Streamlit application

Run the following command from the repository root:

```powershell
streamlit run day5_ex2_trainer_app.py
```

Streamlit will print a local URL in the terminal. Open that URL in your browser to use the dashboard.

> Do not start the Streamlit app with `python day5_ex2_trainer_app.py`. Use `streamlit run` so Streamlit can create its app session and browser interface.

## Gemini retention advisor (optional)

The retention advisor uses the Gemini 2.5 Flash model when a Gemini API key is configured. If the API key is unavailable or the Gemini request fails, the application falls back to local rule-based retention suggestions.

For local development, provide the key through an environment variable named `GEMINI_API_KEY`. Do not hard-code the key in either Python file and do not commit it to GitHub.

For Streamlit Community Cloud, store secrets in the app's **Settings → Secrets**. The application code must read the key from `st.secrets` (as well as the environment variable, if desired) before creating the Gen AI client. Never add the actual API key to this README or to the repository.

## Deploy to Streamlit Community Cloud

1. Push this repository to GitHub.
2. Confirm that the repository contains `day5_ex2_trainer_app.py`, `customer_churn.csv`, `requirements.txt`, and the required files in `models/`.
3. Open [Streamlit Community Cloud](https://share.streamlit.io/) and sign in with GitHub.
4. Create a new app and select this repository, the deployment branch, and `day5_ex2_trainer_app.py` as the main file.
5. Add the Gemini API key in the app's Secrets settings only if the Gemini integration is enabled and the code reads from `st.secrets`.
6. Deploy the app and open the URL provided by Streamlit.

The deployed app must not depend on files stored only on a local computer. Keep the required dataset and model artifacts in the repository (or configure an appropriate external storage solution) and use repository-relative paths.

## Notes and limitations

- The dashboard's churn prediction depends on the quality and representativeness of the training data.
- The current model-selection logic chooses by Accuracy, while Recall is also reported for comparison.
- Feature-importance values describe how the fitted model uses the available features; they should not be interpreted as proof of cause and effect.
- The dashboard expects the input fields and category values to be compatible with the training data and saved feature columns.
- Do not publish real customer information or other sensitive data in a public repository. Use an approved, anonymized, or synthetic dataset.
- Only load Joblib/pickle artifacts from a trusted source.
